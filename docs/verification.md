The current tests include select/text/search/date/local datetime/number filters, value rejection, matched-form default preservation, duplicate-field preservation, approved external attachments, cross-origin cookie separation, bounded descriptor eviction/reauthentication, and DNS destination validation. They exercise synthetic scenarios; they do not reproduce every institutional layout.

The login adapter preserves the selected observed submit control's name/value, including an empty value such as `yt0=`. Multiple controls require an unambiguous Login/Log in/Sign in choice; conflicting fields and unsafe form destination/method overrides are rejected before credentials are sent. Omitting the observed submit control initially caused an unchanged login form without a validation error; a complete submission initially exposed a credential rejection. Updated authorized credentials later authenticated successfully through the API.

Initial local socket creation failed with `PermissionError` (errno 1), and the browser initially reported `ERR_CONNECTION_REFUSED`. Those observations preceded the later permission/environment change; the subsequent TCP and Swagger checks above succeeded.
